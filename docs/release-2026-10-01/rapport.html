6. Authentification & Sécurité

FAIL
P0 — Colonne administrateur modifiable

Backend : UPDATE sur users.is_admin autorisé au rôle authenticated ; policies de mise à jour de sa propre ligne ; aucun trigger utilisateur protégeant les colonnes privilégiées. Cela permet selon la configuration inspectée une élévation via son profil. Aucun changement de privilège n’a été tenté. Protéger aussi INSERT/upsert, suspended et les champs Stripe/validation professionnelle.

PASS
Cache séparé entre sessions — corrigé localement

AuthProvider purge QueryClient à chaque changement d’identité et invalide les réponses de profil obsolètes. Quatre tests couvrent déconnexion, passage A→B, renouvellement de jeton et requête en vol. Ces corrections ne sont pas encore dans la version publiée.

WARN
Stockage des sessions

Le client natif se replie silencieusement vers AsyncStorage en cas d’erreur SecureStore. getItem/removeItem ne nettoient pas systématiquement les deux supports. Établir un stockage natif sécurisé sans retour en clair en production et une migration contrôlée.

WARN
Profil indisponible sur réseau lent

Un timeout de profil produit un utilisateur sans rôle, pouvant renvoyer un compte existant vers le choix de rôle. La correction de cet audit évite un ancien profil après logout et l’email de bienvenue sur erreur SQL, mais ne refond pas la reprise réseau.

PASS
Suppression accessible dans le code

Les deux profils proposent la suppression avec confirmation et une Edge Function dédiée. Son exécution effective, nettoyage Storage, conservation comptable et révocation des accès doivent être testés sur un compte jetable.

7. Paiements & Monétisation

PASS
Services physiques et Stripe

Le modèle décrit concerne des prestations réalisées dans des logements. Il relève des moyens de paiement externes pour services physiques (Apple 3.1.3(e)), sous réserve de conserver ce périmètre.

FAIL

Reproduction locale du code déployé : mission inexistante, montant 50 centimes, lookup en erreur → HTTP 200 et création Stripe simulée. Aucun débit réel. Recalculer et autoriser côté serveur, lier le PaymentIntent au dossier, vérifier montant/devise/payer dans le webhook.

Liste des noms des secrets du projet réel : STRIPE_WEBHOOK_SECRET absent. stripe-webhook v7 dépend de ce secret pour valider les signatures. Sa présence et la livraison effective d’un événement signé sont indispensables.

FAIL
Configuration locale de production en mode test

frontend/.env.production contient une clé publique Stripe pk_test_. Ce constat ne prouve pas le contenu des variables EAS distantes : inspecter l’environnement de la build réellement soumise, puis valider la concordance client/serveur/webhook en live.

WARN
Reprise webhook et divergence du dépôt

Le webhook marque un événement traité avant les effets métier et traite toute erreur d’insertion comme doublon ; les erreurs renvoyées par functions.invoke peuvent être ignorées. Le déployé comprend interventionId, absent de certaines versions locales : réconcilier avant déploiement et tester un retry après panne.
